# 游戏 UI 设计

借鉴 award-level 前端设计理念，让游戏 UI 具有精心设计感、高级感和克制感。目标是让界面看起来像"被设计过的"而非"功能堆砌的"。

## 设计三步法

在开始 UI 之前，先写下三件事：

1. **视觉主旨**：一句话描述界面气质、材质和能量
   - 例："暗黑科技感的霓虹 HUD，冷冽金属与发光边缘的交织"
   - 例："粉嫩像素的 Y2K 复古界面，糖霜质感按钮与 CRT 扫描线"

2. **内容计划**：主界面 → 游戏内 HUD → 结算界面 → 设置界面
   - 每个界面一个职责，一个主导视觉概念
   - 给每个界面一个核心信息或一个核心操作

3. **交互主旨**：2-3 个动效想法，改变界面感受
   - 一个入场序列（主菜单）
   - 一个滚动/粘性效果（游戏内 HUD）
   - 一个悬停/交互反馈（按钮、卡片）

## 界面设计原则

### 克制构图
- 优先使用构图，而非组件堆砌
- 品牌/游戏名放在最显眼的位置
- 一个强视觉锚点，而非多个分散元素
- 用留白、对齐、比例、裁剪、对比来组织，而非加边框和阴影

### 去卡片化
- 默认无卡片布局
- 用分区、列、分割线、列表、媒体块替代卡片
- 卡片仅在"卡片本身就是交互"时使用
- 如果一个面板去掉卡片样式仍然有意义，就移除卡片

### 字体限制
- 最多两个字体族
- 标题字体：Geist、Outfit、Cabinet Grotesk、Press Start 2P（像素风）
- 正文字体：系统字体栈，保证可读性
- 建议搭配：Press Start 2P + system-ui（像素游戏），Satoshi + JetBrains Mono（现代游戏）
- 禁止用 Inter 作为默认字体
- 禁止 Fraunces 和 Instrument_Serif 作为默认衬线字体

### 色彩校准
- 最多 1 个强调色，饱和度 < 80%
- 默认暗色主题：近黑底色 + 柔和白文字 + 单一强强调色
- 禁止"AI 紫色/蓝色发光"作为默认美学
- 调色板锁定：选好一个强调色后，全页面统一使用

```javascript
// 推荐的暗色游戏配色方案
const GAME_PALETTES = {
  // 暗黑科技
  darkTech: { bg: '#0a0a0f', surface: '#14141a', text: '#e8e8f0', accent: '#00f0ff', danger: '#ff4757' },
  // 粉嫩 Y2K 像素
  pixelY2K: { bg: '#1a0a14', surface: '#2a0a24', text: '#ffe8f0', accent: '#ff6b9d', danger: '#ff3366' },
  // 赛博朋克
  cyberpunk: { bg: '#0a0a0a', surface: '#141414', text: '#f0f0f0', accent: '#ff00ff', danger: '#ff3300' },
  // 自然清新
  nature: { bg: '#0a0f0a', surface: '#0f1a0f', text: '#e0f0e0', accent: '#44ff44', danger: '#ff4444' },
  // 极简白（浅色）
  minimal: { bg: '#fafafa', surface: '#ffffff', text: '#1a1a1a', accent: '#1a1a1a', danger: '#ff3b30' },
}
```

### 形状一致性
- 选一种圆角体系并贯穿始终：
  - 全直角（radius 0）：现代、锋利
  - 全柔和（radius 12-16px）：友好、圆润
  - 全药丸（full radius）：按钮专用
- 不容许混用：圆形按钮出现在方形卡片中 = 设计事故

## 游戏 UI 组件设计

### 主菜单 (Main Menu)

```
结构：
┌──────────────────────────────┐
│                              │
│         [游戏 Logo]           │  ← 品牌第一，最大最显眼
│      一句话副标题             │  ← 品牌第二
│                              │
│     [  开始游戏  ]            │  ← 主 CTA，第三
│     [  继续游戏  ]            │  ← 次要 CTA
│                              │
│  设置 排行榜 关于             │  ← 第四
│                              │
│      v1.0.0  © 2026         │  ← 底部信息
└──────────────────────────────┘
```

**设计规则：**
- Logo 必须是界面中最响亮的元素
- 品牌优先于标题，标题优先于正文，正文优先于 CTA
- 主按钮：一个强的视觉焦点，不用多个等大按钮
- 背景：全屏视觉锚点（动画粒子、渐变、3D 场景），不能是纯色
- 删除 30% 的文案后如果界面更好，就继续删

**禁止：**
- 主菜单用卡片网格布局
- 多个同等大小的按钮分散注意力
- 无视觉锚点的纯色背景
- 标签堆叠（pill soup）
- 浮动仪表盘或数据面板

### 游戏内 HUD (In-Game HUD)

```
结构：
┌──────────────────────────────┐
│ ♥♥♥♥♥    SCORE: 12,340     │  ← 顶部状态栏
│                              │
│                              │
│          [游戏区域]           │  ← 最大化游戏区域
│                              │
│                              │
│  [虚拟摇杆]     [A] [B]     │  ← 底部控制区（移动端显示）
└──────────────────────────────┘
```

**设计规则：**
- HUD 最小化，不遮挡游戏画面
- 状态信息用半透明背景叠加
- 信息层级：血量 > 分数 > 道具 > 其他
- 字体大小随屏幕自适应：`clamp(12px, 3vw, 20px)`
- 移动端控制区在安全区域内

**禁止：**
- HUD 占屏幕超过 20%
- 复杂装饰边框
- 多个竞争性强调色
- 装饰性图标（不提升可读性的图标）

### 暂停/设置界面

```
结构：
┌──────────────────────────────┐
│         暂停                  │
│                              │
│     [  继续游戏  ]            │
│                              │
│  音效        ──●─────────    │
│  BGM         ────●───────    │
│  语言         🇨🇳 🇺🇸 🇯🇵 🇰🇷  │
│  画质        低 · 中 · 高     │
│                              │
│     [  返回主菜单  ]          │
└──────────────────────────────┘
```

**设计规则：**
- 半透明遮罩 + 毛玻璃效果
- 设置项用滑条或分段控制器，而非下拉菜单
- 语言切换用国旗图标按钮
- 选项文字在上，控件在下

### 结算界面 (Game Over / Victory)

```
结构：
┌──────────────────────────────┐
│                              │
│      GAME OVER / YOU WIN!    │  ← 大字标题
│                              │
│       SCORE: 12,340          │  ← 分数（大号数字）
│     🏆 NEW HIGH SCORE!       │  ← 新纪录提示
│                              │
│     [  再来一次  ]            │  ← 主 CTA
│     [  分享成绩  ]            │  ← 次要 CTA
│     [  返回主页  ]            │
│                              │
└──────────────────────────────┘
```

**设计规则：**
- 结果文字要大、要醒目
- 分数用大号加粗数字
- 新纪录用特殊动画（弹跳、发光、粒子）
- 主 CTA 视觉突出，引导重玩
- 失败界面不要过于沮丧（保持"再来一次"的欲望）

## 动效设计

### 动效强度分级
- **1-3（静态）**：仅 CSS :hover 和 :active，无自动动画
- **4-7（流体 CSS）**：transition + animation-delay 级联，transform 和 opacity 为主
- **8-10（高级编排）**：入场序列、滚动触发、悬停物理

### 游戏 UI 动效清单
至少实现 3 个有意识的动效：

1. **主菜单入场序列**：Logo 缩放淡入 → 按钮依次上移淡入
2. **游戏内 HUD 过渡**：分数变化时数值跳动，血量变化时闪烁
3. **按钮交互反馈**：`:active` 时 `scale(0.97)` 或 `translateY(1px)` 模拟按压

### 动效规则
- 快节奏（< 300ms），不拖沓
- 使用 `cubic-bezier(0.16, 1, 0.3, 1)` 缓出
- 移动端流畅
- 如果纯粹是装饰性动效，移除
- 任何动效 > 强度 3 必须支持 `prefers-reduced-motion`

```javascript
// 动效禁用检测
const reduceMotion = window.matchMedia('(prefers-reduced-motion: reduce)').matches
const duration = reduceMotion ? 0 : 300
const easing = 'cubic-bezier(0.16, 1, 0.3, 1)'
```

### 禁止的动效
- `window.addEventListener('scroll')` 驱动动画（用 IntersectionObserver）
- 无限循环的微动效（非必要不循环）
- 纯装饰性弹跳、脉冲
- 自定义鼠标光标

## 游戏 UI 硬规则

- 默认无卡片
- 默认无主菜单卡片网格
- 每个界面一个主导视觉概念
- 品牌/游戏名必须是最响亮的元素
- 每屏最多一个强调色
- 最多两个字体
- 按钮文字必须一行显示（桌面端）
- 背景模糊时提供 solid-fill 回退
- 暗色主题 + 浅色主题双模式
- 移动端控制区不遮挡游戏画面

## 界面检查清单

- [ ] 品牌/游戏名在第一屏是否清晰无误？
- [ ] 是否有一个强视觉锚点（而非多个分散元素）？
- [ ] 只看标题能否理解当前界面？
- [ ] 每个界面是否只有一个职责？
- [ ] 卡片真的必要吗？（优先无卡片）
- [ ] 动效是否增强了层级或氛围（而非纯装饰）？
- [ ] 去掉所有装饰性阴影后，设计是否仍然高级？
- [ ] 横屏/竖屏/小屏下是否都正常？
- [ ] 触屏 44x44px 最小点击区域是否满足？
- [ ] 按钮文字是否可读（对比度 WCAG AA）？
